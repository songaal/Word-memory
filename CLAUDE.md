# Word Story — Project Rules

## Versioning (MANDATORY — apply on every change)

The app version is shown in the About card on the Me tab in `public/index.html`:

```html
<span class="version-tag">v2.52.0</span> · <span class="version-date">2026/11/08</span>
```

1. **Always bump the version** — no commit should leave the version unchanged.
2. **Patch (third digit)**: bug fix, style tweak, or small change. e.g. v1.0.0 → v1.0.1
3. **Minor (second digit)**: new user-facing feature (reset patch to 0). e.g. v1.0.x → v1.1.0
4. **Date**: update to today's date in `YYYY/MM/DD` format every time.

**Current version: v2.52.0 — 2026/11/08**

## How to start a new session (read this first)

This file is the context for new conversations. Read **Code map** and **Where to change things** first; the long **Architecture** section below is the detailed feature reference (search it for the feature you are touching).

Describe code by section headers and function names, not line numbers (they drift).

### src/index.js — the Worker

`export default { fetch }` routes `/api/*`; app screen paths (`APP_PATH`: `/story`, `/words/test`, `/me/voice` …) get `index.html`; anything else → `env.ASSETS`. Groups: auth (`login`, `newSession`, `linkEmail`, `logout`, `me`, `currentUser` reads `Authorization: Bearer <session>`), TOTP (`totp*`), words (`getWords`/`putWords` with the 409 conflict check), journal (`getJournal`/`putJournal`, per-entry merge), video (`video()` handles `/api/video/*`), settings (`getSettings`/`putSettings`, whitelist `SETTING_FIELDS`), dictionary (`lookup` → `fromMerriamWebster` + `fromThesaurus`, `freqRank`). Helpers: `json()`, `MAX_BODY`.

### Data (per user, KV `wm:words:<sub>`; plus `wm:extra:<sub>` and shared `wm:note:<word>`)

`{cards, seed, log, history, stories, updatedAt}`. A card: `{word, phonetic, audio, meanings:[{pos, defs:[{d, ex, stage, due, last, v:2, exKo, exKoSrc}]}], synonyms, added, addedAt, learned, sample?}` — **the schedule lives on each def (example sentence)**, not on the card. A story: `{id, title, text, words, entries, created, last, tries, ko, koSrc, chunks, chunkSrc}`. Settings are separate (`wm:settings:<sub>`), journal separate (`wm:journal:<sub>`), video data separate (`wm:vt:` / `wm:vtr:` / `wm:vhist:`). **Extra** (`wm:extra:<sub>`, client `XT`, local cache `wm.extra.<sub|guest>`): `{sentences:[{id, text, ko, vid, title, at, updated, deleted?}], vtests:[{id, at, kind:'video'|'jn', vid, jid, mode, title, total, ok, secs, quit, items:[{t, ok, a ('(skipped)' for Skip)}], retry?:{ok, total, items}}], paused:{at, data|null}}` (`paused` = one test saved for later, `xtPaused()`/`xtSetPaused()`; the newer `at` wins on merge)` — saved sentences (Writing → Sentences) and video test results, merged per item. **Word notes** (`wm:note:<word>`, shared by all users): `{text, at, by, history:[{at, by, text, kind:add|edit|clear}]}` (50 history lines max).

## Where to change things

- **Add a bottom tab**: markup `<section class="screen" id="s-x">` + a button `#tab-x` in `nav.tabbar`; add `'x'` to `TABS`; render it in `show()`; add `rerenderCurrent` / popstate handling if it has sub-pages.
- **Add a sub-tab (segment)**: `.seg` buttons + `.pane`s inside the screen; a `xPane` variable and a `renderX()` that toggles panes (see `renderDict`, `renderStoryTab`, `renderWrite`).
- **Add a setting synced to the account**: add the field to `SETTINGS0` (client) **and** `SETTING_FIELDS` (worker, with a max length; values may not contain spaces), read it with a helper (see `slashCfg`, `vRewind`), save with `setSlash(key, value)` (generic `settings[k]=…; storeSettings()`). Per-device prefs use localStorage `wm.<name>` (`lsGet`/`lsSet`/`lsJSON`).
- **Add a settings page**: `.mepage#me-<id>` markup (copy `me-slash`) + an entry in `SETTINGS_MENU` `{id, title, icon, value, render}`.
- **Add a field to cards / stories**: set it where items are created (`newDef`, `lookup`, JSON import, `(c.addedAt=…, cards.unshift(c))` sites), make `mergeData` keep it when two copies meet, and if old data needs converting add a step to `migrate()` (guard it so it runs once, like `d.v`).
- **Change the review schedule**: `INTERVALS`, `grade()` in `schedule test`, `stageLabel`, `STAGE_OF` (list chips), the Home stage boxes in `renderHome`; old data needs a `migrate()` step.
- **Call an AI**: `aiComplete(system, user, p, {maxTokens, stream})` for one JSON answer, `aiChat(system, messages)` for a conversation (plain text), `aiVision(prompt, images)` for photos. Always check `aiKey()` first and point to Me → Settings → AI when it is missing.
- **Add a worker endpoint**: a route line in `fetch`, a handler using `currentUser`, `json()`; keys start with `wm:`; document it in the Backend section below.
- **Any UI text**: write it in English and add the Korean to `I18N_KO` (exact string) or `I18N_KO_RE` (pattern). Mark learning content `data-noi18n` or add a selector to `I18N_SKIP`. Check for an existing key before adding (duplicate keys silently override).
- **Page URLs (v2.49.0, paths since v2.49.1)**: every screen has its own path so a copied link opens the same screen elsewhere; values that pick an item stay in the query: `/` (Home) · `/story`, `/story/test`, `/story?id=<story id>` · `/words` (word list), `/words/dictionary`, `/words/test` · `/video`, `/video?v=<YouTube id>&s=<sentence, 1-based>` · `/writing` (Translate), `/writing/journal`, `/writing/sentences` · `/me`, `/me/<SETTINGS_MENU id>`. The Worker serves `index.html` for these paths (`APP_PATH` at the end of `src/index.js`, GET only; other unknown paths stay 404), so **every asset link in `index.html` must be absolute (`/icons/…`, `/manifest.json`)**. Old v2.49.0 links (`?tab=…&view=…&page=…`) are still parsed (`URL_DICT_OLD`, `URL_WRITE_OLD`) and rewritten on load. `urlNow()` builds the URL from state (`curTab`, `dictPane`, `storyPane`/`storyView`, `V.vid`/`V.cur`, `writePane`, `mePage`) using `URL_TAB`/`URL_DICT`/`URL_WRITE` ('' = the bare tab path); `urlSync()` (no-op until the first render) **pushes a history entry for every screen change** (v2.49.2 — the user wants back to walk through screens; iOS Chrome also ignores replaceState in its address bar): each entry's state has `u` = its URL plus markers `video`/`story`/`me` (`urlMarks`); an entry pushed by older code without `u` (opening a story/video/settings page, overlays) just gets the URL (replace); a change with the same `urlKey` (only `?s=` differs, i.e. the video sentence) replaces. It is called at the end of `show`, `renderDict`, `renderStoryTab`, `renderStories`, `renderWrite`, `openMePage`, `openVideo`, `closeVideo`, `vHighlight`. `popstate` closes overlays first (sheet / word popup have no entry of their own, so `urlRestore` pushes the screen entry `urlLast` back), then `routeApply(parseRoute())` shows the screen the URL names (tab, sub-tab, story page, settings page, opens/closes the video; `urlApplying` stops pushes meanwhile). `show()` wraps the renderers (`showIn`) and always runs `urlSync()` in `finally`, so a renderer error can't freeze the address (v2.49.3). Me → About shows a small diagnostic line `#urlDbg` only after an error (path · history length · last error `urlErr`, from `window` errors and history calls). On start `ROUTE` (= `parseRoute()`) is parsed; the first `renderAll` runs `routeBoot` (tab/sub-tab) and `routeAfter` (story page, settings page, video — each pushed as its own history entry so back returns to the tab; `V.startS` makes `openVideo` select `?s=`; a story missing from the cache is retried once when account data arrives). Video ⋯ and story ⋯ menus have **Copy link** (`urlFull()`, for the home-screen app with no address bar). A new screen or sub-tab needs a key in `URL_*`/`urlNow`/`ROUTE`, a `urlSync()` call, and its first path segment added to `APP_PATH`.
- **Navigation / back gesture**: use `window.history`. The test-history array is the global **`testHist`** (renamed from `history` in v2.49.4: a global named `history` broke Chrome for iOS, whose injected script wraps pushState/replaceState and calls them on the bare `history`, so the address bar never changed; never declare a global called `history` again). Its saved data key is still `history`. Push a state when opening a page-like view and handle it in the `popstate` listener (scoped by `curTab`).
- **Bottom sheets**: `openSheet(title, html)` / `closeSheet()`; word popup `openPop(card)`; a sheet that must stay open over others needs its own element with a higher z-index (see `#pracSheet`, `#vchat`).

## Local testing

1. `node dev/server.mjs` (keep it running in the background) → http://localhost:8787. In the browser set localStorage `wm.session` / `wm.user` as described at the top of that file (or `wm.guest=1`), reload.
2. Syntax check after editing: extract the last `<script>` of `public/index.html` to a temp file and run `node --check` on it; `node --check src/index.js`.
3. Drive the UI with Playwright (Chromium is pre-installed in the cloud sandbox): open the page, click through the changed flow, read DOM state with `page.evaluate`, take screenshots and look at them (both `wm.lang` `en` and `ko`). Mock outside services with `context.route(...)` (Google sign-in script, Google Translate/TTS, AI APIs, YouTube iframe API) — the sandbox cannot reach most outside hosts.
4. Then commit, push to `main`, and wait for the "Workers Builds: word-memory" check (`gh api repos/songaal/Word-memory/commits/<sha>/check-runs`).

## Architecture

- **Frontend**: `public/index.html` — single-file app, no build step. UI text is written in English in the code and shown in **English or Korean** (see Language below). **Duolingo-style look**: Nunito UI font (Literata stays for sentences/stories), **lime-green brand** `--brand` #58cc02 with white `--on-brand` text (buttons, Today's goal hero, + button), blue accents (`--accent`, selected tab), **coral** for stories (the user tried violet and honey yellow and chose green); buttons with a 3D bottom shadow (`.btn`, variants `.ghost .blue .orange .purple .coral .green .danger`), 2px-bordered rounded cards, tokens `--brand/--green/--blue/--orange/--gold/--purple/--coral/--red` (+ `-d` darker, `-soft`), dark mode too. App name **Word Story** (title, `manifest.json`); icon = a capybara face filling the icon (deadpan flat-lidded eyes, darker snout, wide nose, long philtrum, sulky mouth) with a mandarin orange on its head, lime-green background (`public/icons/icon.svg` → 192/512 PNG + `apple-touch-icon.png`; make the small PNGs by downscaling the 512 render, and bump the `?v=` on icon links when they change).
  - Native-app shell: fixed full screen, no zoom (viewport + gesture blocking), no pull-to-refresh, one scroll area per tab, bottom tab bar: **Home** (greeting + 🔥 streak pill, green "Today's goal" hero (always green) with a gold progress bar and Start words test; when the goal is done the button is replaced by a ✓ badge and "correct today" / "sentences tomorrow" tiles, a full-width Story test card (the old Words test card was removed: the hero is the one way into the words test) that starts `nextStory()`: newest untested, else lowest score — colored stat tiles, colored review-stage boxes (7: 0d 1d 3d 7d 14d 30d 60d; Mastered = 30+ days, stage ≥ 5), 7-day chart), **Story** (top seg Stories | Test — `storyPane` 'list'|'test', `renderStoryTab`, panes `pane-story` / `pane-stest`), **Words** (Dictionary | Words | Test — `dictPane` 'search'|'list'|'test', the Test pane is the words test, due badge on this tab), **Video** (YouTube repeat listening, see below), **Writing** (Translate / Journal / Sentences, `s-write`, `writePane` 'tr'|'jn'|'sn' in localStorage `wm.writePane`), **Me** (profile + settings menu). Internally the Words tab still uses `dict` ids. Tapping the Words tab always opens the Words sub-tab (word list) (v2.42.0); `openWordsTest()` still goes to Test. Text can't be selected by dragging (inputs excepted). `.view` is sized to the visual viewport (`--vvh`/`--vvtop` from `visualViewport`), so when the iOS keyboard opens the bars and search box stay put and only the inner list scrolls; bottom sheets (`.sheet`) use the same visible area, and a field focused inside a sheet is scrolled to the middle after the keyboard opens. The tab bar hides while an input has focus (keyboard up), via `body.kb`, and during a running test, via `body.intest` (set by `setQuit`). On the Words and Story tabs (not their Test panes), the Video list and Writing → Journal (v2.47.2) it slides down while scrolling down and back up on scrolling up (`setTabbarHidden` → `body.tbhide`; shown again near the top and whenever the screen changes — tab, pane (also when code switches it, e.g. Select → story form), or story list ↔ story page (`tbScreenIs`)). Popups use a bottom sheet. The selected tab's icon is filled.
  - **There is no Test tab** (removed v2.39.0): the words test lives in Words → Test, story tests in Story → Test. `testPane` ('schedule' = words, 'story') says which one is showing; `openWordsTest()` / `openStoryTest(id)` navigate there; `setQuit` moves the timer/Hint/Quit box `#testBarR` into the header of the right tab (`#dictBarEl` / `#storyBarEl`); `testSegHide` hides that tab's sub-tabs during a test; `tmrShould` counts only while that test pane is on screen.
  - **Story reader + slash reading (끊어읽기)**: a story page has play ▶/⏸ (resumes where it paused, `srPos`), stop ■, translate toggle and a level dropdown `#svLv` (No chunks / Small / Medium / Large chunks = `none|s|m|l`, in that order); ⋯ (`openStoryMenu`, bottom sheet) has text size Small/Large (per device, localStorage `wm.srFont`), Slash reading settings, Edit story, Delete story. **No chunks** = the classic view (tappable words, study words as buttons, Google paragraph translations `s.ko`, sentence-by-sentence reader `startReading`). A slash level shows chunks (`slashHTML`: EN over KO, orange `/`, study words bold; tap a chunk to play from it) from `s.chunks` (`{title, sentences:[{en,ko,s,m,l}]}`, valid while `s.chunkSrc===s.text`, synced with the word list, kept in `mergeData`), generated once by **the AI chosen in Me → Settings → AI** (`loadChunks`: the text is cut into parts of a few paragraphs (~700 chars, `chunkBatches`), up to 4 requests at a time with a "done / total · seconds" line (`chunkJobs`, `chunkTick`), each `chunkPart` → `aiComplete(…, {maxTokens:16000, stream:true})` — Claude is streamed (`claudeStream`, SSE, gives up only after 60 s with no data) so long replies are not cut off, same key/model as the story writer, called from the browser; `CHUNK_PROMPT` kept exactly as the original slash-reader prompt, checked by `chunkValid`, one retry; no AI key → a message pointing to Settings → AI; ≤8,000 chars); sentences are mapped back to paragraphs by `slashParas`. Playback (`slashPlay`): each chunk EN at the slash speed, then (translation on) its Korean (ko-KR voice, speed +0.1), then the pause; uses the app's Voice engine (`srSay` → `gSay(text,voice,rate)` / `lpDevice(text,ko,rate)`). Changing level keeps the sentence position. Settings `slashLevel/slashTr/slashRate/slashPause` (default none / on / 0.9 / 1 s) are account settings (`slashCfg`, `setSlash`), also on Me → Settings → **Slash reading** (`renderSlash`: level cards with examples, speed 0.7–1.1, pause 0–2 s, translation show/hide).
  - **Video tab** (ported from the video-repeat-player app, v2.40.0; `s-video`, state object `V`, icons `VI`): list pane `#vpane-list` (link box + Paste + Go, `vExtract` accepts youtu.be / watch?v= / shorts / embed / bare id; recent videos `V.hist` with thumbnail, day, ✕) and player pane `#vpane-play` (`openVideo(vid)` pushes `{video}` history state so the back gesture returns, `closeVideo`; the big header and the bottom tab bar hide, `body.vplay`). YouTube IFrame API loaded on first use (`vYTReady`), `controls:0`, captions module unloaded; title from YouTube oEmbed. **Play bar on the video** (v2.50.0, `#vBar` inside `#vWrap`, always shown, dark gradient): ▶/⏸ toggle `#vPP` (`vTap`, icon from `onStateChange` → `vPPIcon`) left of the seek bar `#vProg` (drag to seek, keeps the drill going); above it "time / total" and "n / total" plus a ⚙ `#vGear` that opens a small panel `#vCset` on the video: **caption size** 11–32 px (slider + A−/A+, live via `--vcap`, per device localStorage `wm.vcapSize`, `vCapSet`; while open with no caption showing it shows the current sentence as a sample). **Tap the video** = play/pause after 280 ms; **double tap** (`vDouble`): left third = previous sentence, right third = next (◀◀/▶▶ flash `#vFlashL/R`, `vFlash`; no transcript → −N/+N s), middle = **full screen** (`vFull`: `body.vfull` hides the title bar, buttons and sentence list, plus the browser Fullscreen API where it exists; double tap again / Esc / leaving the video exits; in portrait the caption starts right under the centred 16:9 picture, `top:calc(50% + 28.125vw + 10px)`). **Zoom in full screen** (v2.51.0, state `vZ`, `vZoomSet`): pointer events on `#vOverlay` (`touch-action:none` in `body.vfull`) — two-finger pinch scales only the YouTube iframe 1–3× around the fingers, one-finger drag moves it when zoomed (pan clamped to the picture), ctrl+wheel = trackpad pinch on a computer; a gesture blocks the tap/double tap for 400 ms (`vZ.block`); pinching back below 1.08× snaps to the original size; an **Original size** pill `#vZReset` shows while zoomed; leaving full screen resets it. Caption and play bar never move. **Keyboard** (`vKeysOn`: player open, no sheet/test/chat, not typing): ←/→ previous/next sentence, Space play/pause, r replay this sentence, `<`/`,` back N s, `>`/`.` forward N s, t Translate, b Blur, v video on/off, s slow, m Time, c CC. Under the video a row of square buttons (video on/off, ← previous, −N s, replay (green), +N s, next →, CC = off/KR/EN/KR-EN (`V_CC`; KR-EN = Korean with the English under it)), and pill toggles: **Repeat 3×** / Play once, 🐢 slow (`setPlaybackRate`), Translate (Korean under each sentence), Blur, Time (per-sentence start/end with < > 0.5 s adjust, saved). Sentence rows (v2.43.0): the number sits left of the text (`.vb`); every word is tappable (`tapWordsHTML` → the English–English dictionary popup `#pop`, video paused); after the text a copy icon (`vCopy`, toast; the per-row AI study icon was removed in v2.50.0 — study now only from the top-bar ✦); tapping anywhere else in the row replays it. **Split a sentence** (v2.50.0): with Time on and the video paused (`#vSents.vpaused`) each row has a ✂ after `< >` (`data-vsplit`, `vSplitOpen`): the row shows its words unblurred, tapping a word puts/removes a `/` at the nearest gap, tapping a `/` removes it (`vSplitTap`, `V.split`), Confirm (`vSplitApply`) splits it into several sentences with times shared by text length, drops that sentence's translation and shifts the later ones (translations are keyed by sentence number), saves transcript + translations. ⋯ → **Update translation** (`vUpdateTr`) translates only the sentences with no translation. **Sentence study**: no AI key → a sheet explaining the feature with Open AI settings; otherwise a Yes/No sheet naming the AI and model, then the chat sheet `#vchat` (z 55, own history state so back closes it): the AI in use (`aiChat(system, messages)` — multi-turn, plain text, Gemini/OpenAI/Claude) answers very briefly in Korean (`VCHAT_SYS`, `vFirstAsk`, v2.43.1): line 1 = the translation, line 2 = one sentence matching each part to its words (주어 I / 동사 was / …), line 3 only if there is a phrasal verb or unusual usage, at most two sentences, replies rendered by `vMd` (paragraphs, bullets, bold), a textarea to keep asking (Enter sends).   - **Sync between devices**: data loads once at start, then `refreshCloud` pulls `/api/words` again when the app returns to the foreground (`visibilitychange`/`focus`) and on tab or sub-tab taps (at most every 15 s), and redraws the current screen (`rerenderCurrent`, no focus change). It skips while local changes are unsent (`dirty`/pending), during a test, or with a sheet/popup open; `saveGen` drops a pull that raced a local change. Settings reload on foreground too.
  - **Versions and merging** (KV is eventually consistent — a read can return an older copy for a minute or more): every saved copy has `updatedAt`; the client keeps `serverAt` (the copy its data is based on, also in the cache) and ignores any read with an older or equal `updatedAt` (refresh and start-up). `PUT /api/words` sends `base: serverAt`; if the stored copy is newer the worker answers **409** with it, and the client merges (`mergeData`: per sentence the schedule with the later `last` wins, daily `log` counts take the max, history and stories are combined, local objects updated in place so a running test keeps working) and saves again. Deleted words/stories can come back from the other copy in a merge.
  - Home stats use `log` (answers per day, `{ 'YYYY-MM-DD': {ok, no} }`), saved with the word list.
  - Dictionary: looked up through `GET /api/lookup` on the worker (never directly from the browser).
  - Sound: dictionary audio for words (device speech as fallback, and for definitions). **Example sentences** (`data-kind="ex"` → `sayExample`), the sentence read on **test reveal**, and **story Listen** use the engine chosen in Me → Settings → Voice: **Google voice** (Google Cloud Text-to-Speech with the Google key from the Google Translate page — the project needs the Cloud Text-to-Speech API; default `en-US-Chirp3-HD-Aoede`, list = en-US/GB/AU Chirp3-HD + Neural2, filtered by an All/US/UK/Australia tab (`voicePref.greg`); key-restriction and API-off errors get plain instructions (`gErrText`) and the voice list retries when the page is reopened; MP3 cached in Cache Storage `wm-tts-v1` so a sentence is fetched once; speed via `playbackRate`; one shared `gAudio`, primed with a silent WAV on a tap for iOS; falls back to device speech on error, `gLastError` shown on the Voice page) or **This device** (Web Speech API; iOS web apps only get basic voices). Me → Settings → Voice picks the engine (`voicePref.engine`, `gvoice`) plus a device English voice and speed (Apple novelty/character and Eloquence voices are hidden: `oddVoice`) (per device, localStorage `wm.voice`); `makeUtter` applies it everywhere. Story page **Listen** reads sentence by sentence, highlights the current paragraph and smoothly scrolls each new paragraph to the upper part of the screen (`reader`, `markReading`; stopped on leaving the page/tab or when anything else speaks).
  - **AI story writer**: Me → Settings → AI picks one of **Gemini / ChatGPT / Claude** (`aiProvider`) and stores that provider's key and optional model (`geminiKey/geminiModel`, `openaiKey/openaiModel`, `claudeKey/claudeModel`; defaults `gemini-flash-latest`, `gpt-4.1-mini`, `claude-haiku-5-5`; table `AI` in the script). "Use for writing stories" (`#aiUse`, radio list) is the only place that picks the provider in use (`aiProvider`; falls back to the first provider with a key if its key is removed). The key card's Gemini/ChatGPT/Claude tabs only choose which key to edit; "Save and test" checks the model endpoint (free) and makes it the one in use only when none is set yet. The story form button names the AI in use. All calls go from the browser (`aiComplete`; Claude uses `anthropic-dangerous-direct-browser-access`). Words → Words has **Select** (`listSel`): tapping words checks them and a bottom bar offers **Test these** (`startTest(set,'Selected words')` with every example sentence of the picked words; due ones count, the rest are practice) **🗑 Delete** (asks first, removes the picked words and their schedules; header has Select all / Clear) and **Make a story** (up to 20 words), which opens the story form with those words filled in (nothing is generated until the user taps Write); the Write button runs `genStory` → `writeStory` (each word's first definition is sent so the sense matches). A "Request for the AI" box (textarea that grows with its text, up to 600 chars) sits on its own line above the full-width Write button (`#stHint`, remembered in localStorage `wm.storyHint`); when filled it leads the prompt and decides format/genre/tone/difficulty (scripts and dialogues come back as `Name: line` with a blank line between lines, since paragraphs split on blank lines); when empty the default is a 2–4 paragraph story. The **Write with <AI> / Write again** button that uses the "Words to learn" box (plain words or JSON). The story is only filled in; the user reviews and taps Save.
  - **Language** (Me → Settings → Language, `#me-lang`, `renderLang`): System default / English / 한국어, stored per device in localStorage `wm.lang` (`auto` default → `DEVICE_LANG` from `navigator.languages`); changing it reloads the app. `LANG`/`LOC()` set `<html lang>` and date formatting. Korean is done by a DOM translator: `I18N_KO` (exact strings) and `I18N_KO_RE` (regex patterns for strings with numbers/names), applied by `trTree` + a MutationObserver to text nodes and `placeholder`/`title`/`aria-label`. Learning content is never translated (`I18N_SKIP` selectors, or `data-noi18n`). **When adding or changing UI text, add its Korean to `I18N_KO` (or a pattern to `I18N_KO_RE`).** Brand/model names, external site button names, AI prompts and speech stay English.
  - Translation: toggle button next to each example sentence → Korean via Google Cloud Translation v2, called from the browser with the user's own API key (Me → Settings → Google Translate). Translations are saved on the card (`exKo`).
- **Backend**: `src/index.js` — Cloudflare Worker
  - `POST /api/auth/login` — verifies a Google ID token, creates a session (KV, 60 days)
  - `POST /api/auth/logout`, `GET /api/me`
  - `GET/PUT /api/words` — the signed-in user's whole word list and answer log (`wm:words:<google sub>` → `{cards, seed, log, history, stories, updatedAt}`); PUT takes `base` and returns 409 `{conflict, data}` when the stored copy is newer
  - `GET /api/note?word=` (no sign-in) / `PUT /api/note?word=` `{text}` (signed in, ≤4000 chars) — shared word notes `wm:note:<word>`; PUT appends `{at, by: user.name, text, kind}` to `history` (50 max); unchanged text is a no-op
  - `GET/PUT /api/extra` — saved sentences + test results + the paused test (`wm:extra:<sub>`); PUT merges with the stored copy (sentences by `updated`, tombstones 60 days, max 2000; tests by id, newest 300 — video tests need a valid `vid`, journal tests `kind:'jn'` + `jid`; `paused` by newer `at`, data <200 KB) and returns the merged record
  - `GET/PUT /api/journal` — the user's journal (`wm:journal:<sub>` → `{entries, updatedAt}`); PUT merges with the stored copy per entry (later `updated` wins; deletions kept as tombstones for 60 days) and returns the merged list
  - `POST /api/auth/totp`, `GET/DELETE /api/totp`, `POST /api/totp/setup`, `POST /api/totp/confirm` — authenticator-app sign-in (see Auth)
  - `GET/PUT/DELETE /api/video/transcript?v=`, `GET/PUT /api/video/translations?v=`, `GET/PUT /api/video/history` (signed in): transcripts `wm:vt:<vid>` and translations `wm:vtr:<vid>` are shared per video (1 year; DELETE leaves a `{deleted:true}` marker); history `wm:vhist:<sub>` (max 100). Falls back to the old app's KV (binding `VIDEO_CACHE`, read only: `<vid>`, `tr:<vid>`, `hist:<email>`).
  - `GET/PUT /api/settings` — the signed-in user's settings, Google Translate API key, AI provider and keys (`wm:settings:<google sub>` → `{translateKey, aiProvider, openaiKey, openaiModel, geminiKey, geminiModel, claudeKey, claudeModel, slashLevel, slashTr, slashRate, slashPause, videoRewind, videoForward, videoSlow}`; `SETTING_FIELDS`). Guests keep settings in localStorage.
  - `GET /api/lookup?word=` — Merriam-Webster Learner's (definition, examples, pronunciation) + Merriam-Webster Thesaurus (similar words), asked together. **Similar words: at most 3** — up to 8 candidates from the thesaurus's main sense (topped up from other senses only if fewer than 3), ranked by `freqRank` (word-frequency list `src/freq.js`, 20k most common English words from google-10000-english, personal/educational use) and the 3 most common kept; empty when MW has none. Cached in KV (`wm:dict3:<word>`, 90 days) once the Thesaurus has answered. `&fresh=1` skips the cache; `&debug=1` adds a `sources` report.
  - No other similar-word source (Datamuse was removed): similar words are optional. The 3-word limit applies only when words are generated (lookup, photo import); existing cards keep and show all their similar words.

(Slash reading needs no server secret: it uses the user's own AI key.) Without the Learner's key, lookups return "unavailable"; without the Thesaurus key, words have no similar words.

- **Auth**: Google Identity Services, same OAuth client as video-repeat-player. **Authenticator-app sign-in (TOTP)** replaced the email-code idea (no mail service needed): Me → Settings → **Authenticator app** (`renderAuth`, signed-in Google users only) → `POST /api/totp/setup` gives a secret + `otpauth://` URI, shown as a QR code (qrcode-generator 1.4.4, loaded on demand from jsDelivr, cdnjs fallback; the key is shown too, with Copy) → the user confirms with a 6-digit code (`POST /api/totp/confirm`) → `wm:totp:<sub>`; Turn off = `DELETE /api/totp`. Gate → "Sign in with an authenticator app": Google email + code → `POST /api/auth/totp` (email must be linked: `wm:email:<email>` written by `linkEmail` at Google sign-in and on `GET /api/settings`); RFC 6238 (SHA-1, 6 digits, 30 s, ±1 step), a used step can't be reused, 5 wrong tries per email per 10 minutes; returns the same `{session, user}` as Google sign-in. The last email used is prefilled (`wm.totpEmail`). The gate scrolls (`#gate{overflow-y:auto}`) and focusing the email/code field scrolls the box to the top so the keyboard doesn't cover it.

## Review schedule

- Stages: 0 (not passed yet: new, or reset) → 1-day → 3-day → 7-day → 14-day → 30-day → 60-day (`INTERVALS=[1,3,7,14,30,60]`, max stage 6). The 1-day step was added in v2.42.0; older data is moved up one stage once (`migrate`, defs get `v:2`; `mergeData` shifts an old-scheme remote stage too).
- Wrong → tomorrow, stage 0.
- Right → next stage: 1, 3, 7, 14, 30, 60 days. (So from stage 0, right or wrong, the sentence comes back tomorrow.)
- Right with 2+ hints → tomorrow, stage unchanged.
- Words already tested today are practice and don't change the schedule.
