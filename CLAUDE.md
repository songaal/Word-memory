# Word Story — Project Rules

## Versioning (MANDATORY — apply on every change)

The app version is shown in the About card on the Me tab in `public/index.html`:

```html
<span class="version-tag">v2.18.1</span> · <span class="version-date">2026/10/19</span>
```

1. **Always bump the version** — no commit should leave the version unchanged.
2. **Patch (third digit)**: bug fix, style tweak, or small change. e.g. v1.0.0 → v1.0.1
3. **Minor (second digit)**: new user-facing feature (reset patch to 0). e.g. v1.0.x → v1.1.0
4. **Date**: update to today's date in `YYYY/MM/DD` format every time.

**Current version: v2.18.1 — 2026/10/19**

## Architecture

- **Frontend**: `public/index.html` — single-file app, no build step. All UI text is English. App name **Word Story** (title, `manifest.json`); icon = open storybook with rising sparkles (`public/icons/icon.svg` → 192/512 PNG + `apple-touch-icon.png`; make the small PNGs by downscaling the 512 render, and bump the `?v=` on icon links when they change).
  - Native-app shell: fixed full screen, no zoom (viewport + gesture blocking), no pull-to-refresh, one scroll area per tab, bottom tab bar: **Home** (stats), **Test** (Schedule / Story), **Words** (Dictionary / Words / Story), **Me** (profile + settings menu). Internally the Words tab still uses `dict` ids. Text can't be selected by dragging (inputs excepted). `.view` is sized to the visual viewport (`--vvh`/`--vvtop` from `visualViewport`), so when the iOS keyboard opens the bars and search box stay put and only the inner list scrolls. The tab bar hides while an input has focus (keyboard up), via `body.kb`, and during a running test, via `body.intest` (set by `setQuit`). On the Words tab's three panes it slides down while scrolling down and back up on scrolling up (`setTabbarHidden` → `body.tbhide`; shown again near the top and whenever the screen changes — tab, pane (also when code switches it, e.g. Select → story form), or story list ↔ story page (`tbScreenIs`)). Popups use a bottom sheet. The selected tab's icon is filled.
  - Me → Settings is a list menu (`SETTINGS_MENU` in the script); each item opens its own page with a ‹ back button, and the phone/browser back gesture also returns. Add future settings to that list.
  - When a test ends, a results screen shows the score and every answer (misses first, tap for the word). Each finished test is saved to `history` (newest first, max 60) and listed under the Start button on the Test tab; tapping one opens the same results page.
  - Learning is example-first: each word card lists numbered example sentences, each with its definition underneath (no number); similar words come last.
  - **Test items are example sentences, not words.** Each definition with an example (`meanings[].defs[]`) has its own schedule: `stage`, `due`, `last`. A word with no example gives one item from its first definition. The answer is typed into a letter-slot blank inside the sentence (`gapHTML`/`setupGap`: one `_` per letter, fixed to the answer's length, a transparent input on top); hints reveal fixed leading letters (1, then +2, then +2) and typing continues after them. On reveal the blank is filled (green right / red wrong) and tapping it opens the word's entry. **Quit** (quiet link at the top right of the Test header, shown only while a test runs) ends the test; the next start begins from the first question.
  - **Stories** (`stories`, saved with the word list): `{id, title, text, words, entries:{word: card|null}, created, last}`. Words → Story lists them (title, first 5 words, date); a story page bolds the study words (any form) and every other word is tappable too (`tapWordsHTML`; looked up on demand and cached in `tapCache`, with + Add in the popup); a Translate toggle shows Korean under each paragraph (one batched Google request; saved on the story as `ko`/`koSrc`, refetched when the text changes); Edit / Delete sit at its top right (editing reuses the form, keeps date and entries, and clears the last score if the text or words changed). Test → Story turns every study-word occurrence into a blank (a Hint toggle shows the story's words alphabetically); Check shows the score and filled story; Quit returns to the list. Story tests don't touch the schedule. The story form's "Words to learn" takes plain words (existing word-list entries are used; others are looked up and added to the word list) or a JSON array in the Add-words format, which also adds/replaces those words in the word list. Seed v3 adds a sample story (`sample-lemonade`, original text).
  - Words → Dictionary: search box at the top (auto-focused when the tab opens), results below with the newest first; looks words up without adding them (+ Add button). Words → Words has a + button for bulk add with two modes: **Words** (one per line, looked up in the dictionary) and **JSON** (prefilled template `[{word, pos, pairs:[{example, definition}], similar:[]}]`; one array per line also accepted). After adding, a results screen lists the new words. JSON import **overwrites** a word already in the list (sentences with unchanged example text keep their schedule and translation); Words mode skips existing words.
  - Any `data-pop="<word>"` element opens that word's entry in the quick popup (`#pop`), a bottom sheet that layers above the main sheet (`#sheet`).
  - **Sync between devices**: data loads once at start, then `refreshCloud` pulls `/api/words` again when the app returns to the foreground (`visibilitychange`/`focus`) and on tab or sub-tab taps (at most every 15 s), and redraws the current screen (`rerenderCurrent`, no focus change). It skips while local changes are unsent (`dirty`/pending), during a test, or with a sheet/popup open; `saveGen` drops a pull that raced a local change. Settings reload on foreground too.
  - Home stats use `log` (answers per day, `{ 'YYYY-MM-DD': {ok, no} }`), saved with the word list.
  - Dictionary: looked up through `GET /api/lookup` on the worker (never directly from the browser).
  - Sound: dictionary audio for words (device speech as fallback, and for definitions). **Example sentences** (`data-kind="ex"` → `sayExample`), the sentence read on **test reveal**, and **story Listen** use the engine chosen in Me → Settings → Voice: **Google voice** (Google Cloud Text-to-Speech with the Google key from the Google Translate page — the project needs the Cloud Text-to-Speech API; default `en-US-Chirp3-HD-Aoede`, list = en-US/GB/AU Chirp3-HD + Neural2; MP3 cached in Cache Storage `wm-tts-v1` so a sentence is fetched once; speed via `playbackRate`; one shared `gAudio`, primed with a silent WAV on a tap for iOS; falls back to device speech on error, `gLastError` shown on the Voice page) or **This device** (Web Speech API; iOS web apps only get basic voices). Me → Settings → Voice picks the engine (`voicePref.engine`, `gvoice`) plus a device English voice and speed (Apple novelty/character and Eloquence voices are hidden: `oddVoice`) (per device, localStorage `wm.voice`); `makeUtter` applies it everywhere. Story page **Listen** reads sentence by sentence and highlights the current paragraph (`reader`, stopped on leaving the page/tab or when anything else speaks).
  - **AI story writer**: Me → Settings → AI picks one of **Gemini / ChatGPT / Claude** (`aiProvider`) and stores that provider's key and optional model (`geminiKey/geminiModel`, `openaiKey/openaiModel`, `claudeKey/claudeModel`; defaults `gemini-flash-latest`, `gpt-4.1-mini`, `claude-haiku-5-5`; table `AI` in the script). "Use for writing stories" (`#aiUse`, radio list) is the only place that picks the provider in use (`aiProvider`; falls back to the first provider with a key if its key is removed). The key card's Gemini/ChatGPT/Claude tabs only choose which key to edit; "Save and test" checks the model endpoint (free) and makes it the one in use only when none is set yet. The story form button names the AI in use. All calls go from the browser (`aiComplete`; Claude uses `anthropic-dangerous-direct-browser-access`). Words → Words has **Select** (`listSel`, up to 20): tapping words checks them and a bottom bar "Make a story with these N words" opens the story form with those words filled in (nothing is generated until the user taps Write); the Write button runs `genStory` → `writeStory` (each word's first definition is sent so the sense matches). A "Request for the AI" box (textarea that grows with its text, up to 600 chars) sits on its own line above the full-width Write button (`#stHint`, remembered in localStorage `wm.storyHint`); when filled it leads the prompt and decides format/genre/tone/difficulty (scripts and dialogues come back as `Name: line` with a blank line between lines, since paragraphs split on blank lines); when empty the default is a 2–4 paragraph story. The **Write with <AI> / Write again** button that uses the "Words to learn" box (plain words or JSON). The story is only filled in; the user reviews and taps Save.
  - Translation: toggle button next to each example sentence → Korean via Google Cloud Translation v2, called from the browser with the user's own API key (Me → Settings → Google Translate). Translations are saved on the card (`exKo`).
- **Backend**: `src/index.js` — Cloudflare Worker
  - `POST /api/auth/login` — verifies a Google ID token, creates a session (KV, 60 days)
  - `POST /api/auth/logout`, `GET /api/me`
  - `GET/PUT /api/words` — the signed-in user's whole word list and answer log (`wm:words:<google sub>` → `{cards, seed, log, history, stories}`)
  - `GET/PUT /api/settings` — the signed-in user's settings, Google Translate API key, AI provider and keys (`wm:settings:<google sub>` → `{translateKey, aiProvider, openaiKey, openaiModel, geminiKey, geminiModel, claudeKey, claudeModel}`; `SETTING_FIELDS`). Guests keep settings in localStorage.
  - `GET /api/lookup?word=` — Merriam-Webster Learner's (definition, examples, pronunciation) + Merriam-Webster Thesaurus (similar words), asked together. Cached in KV (`wm:dict2:<word>`, 90 days) once the Thesaurus has answered. `&fresh=1` skips the cache; `&debug=1` adds a `sources` report.
  - The browser tops up similar words from Datamuse when the Thesaurus gives fewer than 4 (Datamuse returns HTTP 403 to Cloudflare Workers).
- **Secrets** (Cloudflare dashboard → Worker → Settings → Variables and Secrets, never in the repo): `MW_LEARNER_KEY`, `MW_THESAURUS_KEY`. Without the Learner's key, lookups return "unavailable"; without the Thesaurus key, similar words come only from Datamuse.
- **Storage**: Workers KV namespace `word-memory`, binding `WORDS`. Keys start with `wm:`.
- **Auth**: Google Identity Services, same OAuth client as video-repeat-player.
- **Deploy**: Cloudflare Workers Builds (GitHub connected in the Cloudflare dashboard) — auto on push to `main`.
  - **Do not push to `main` until the user asks to deploy.** Verify changes locally first (local worker + browser test), commit locally, and push only on request.
- **URL**: https://word-memory.songaal.workers.dev

## Review schedule

- Wrong → tomorrow, stage reset.
- Right → 3, 7, 14, 30, 60 days.
- Right with 2+ hints → tomorrow, stage unchanged.
- Words already tested today are practice and don't change the schedule.
