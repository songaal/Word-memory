# Word Story — Project Rules

## Versioning (MANDATORY — apply on every change)

The app version is shown in the About card on the Me tab in `public/index.html`:

```html
<span class="version-tag">v2.41.2</span> · <span class="version-date">2026/10/30</span>
```

1. **Always bump the version** — no commit should leave the version unchanged.
2. **Patch (third digit)**: bug fix, style tweak, or small change. e.g. v1.0.0 → v1.0.1
3. **Minor (second digit)**: new user-facing feature (reset patch to 0). e.g. v1.0.x → v1.1.0
4. **Date**: update to today's date in `YYYY/MM/DD` format every time.

**Current version: v2.41.2 — 2026/10/30**

## Architecture

- **Frontend**: `public/index.html` — single-file app, no build step. UI text is written in English in the code and shown in **English or Korean** (see Language below). **Duolingo-style look**: Nunito UI font (Literata stays for sentences/stories), **lime-green brand** `--brand` #58cc02 with white `--on-brand` text (buttons, Today's goal hero, + button), blue accents (`--accent`, selected tab), **coral** for stories (the user tried violet and honey yellow and chose green); buttons with a 3D bottom shadow (`.btn`, variants `.ghost .blue .orange .purple .coral .green .danger`), 2px-bordered rounded cards, tokens `--brand/--green/--blue/--orange/--gold/--purple/--coral/--red` (+ `-d` darker, `-soft`), dark mode too. App name **Word Story** (title, `manifest.json`); icon = a capybara face filling the icon (deadpan flat-lidded eyes, darker snout, wide nose, long philtrum, sulky mouth) with a mandarin orange on its head, lime-green background (`public/icons/icon.svg` → 192/512 PNG + `apple-touch-icon.png`; make the small PNGs by downscaling the 512 render, and bump the `?v=` on icon links when they change).
  - Native-app shell: fixed full screen, no zoom (viewport + gesture blocking), no pull-to-refresh, one scroll area per tab, bottom tab bar: **Home** (greeting + 🔥 streak pill, green "Today's goal" hero (always green) with a gold progress bar and Start words test; when the goal is done the button is replaced by a ✓ badge and "correct today" / "sentences tomorrow" tiles, a full-width Story test card (the old Words test card was removed: the hero is the one way into the words test) that starts `nextStory()`: newest untested, else lowest score — colored stat tiles, colored review-stage boxes, 7-day chart), **Story** (top seg Stories | Test — `storyPane` 'list'|'test', `renderStoryTab`, panes `pane-story` / `pane-stest`), **Words** (Dictionary | Words | Test — `dictPane` 'search'|'list'|'test', the Test pane is the words test, due badge on this tab), **Video** (YouTube repeat listening, see below), **Writing** (Translate / Journal, `s-write`, `writePane` in localStorage `wm.writePane`), **Me** (profile + settings menu). Internally the Words tab still uses `dict` ids. Text can't be selected by dragging (inputs excepted). `.view` is sized to the visual viewport (`--vvh`/`--vvtop` from `visualViewport`), so when the iOS keyboard opens the bars and search box stay put and only the inner list scrolls; bottom sheets (`.sheet`) use the same visible area, and a field focused inside a sheet is scrolled to the middle after the keyboard opens. The tab bar hides while an input has focus (keyboard up), via `body.kb`, and during a running test, via `body.intest` (set by `setQuit`). On the Words and Story tabs (not their Test panes) it slides down while scrolling down and back up on scrolling up (`setTabbarHidden` → `body.tbhide`; shown again near the top and whenever the screen changes — tab, pane (also when code switches it, e.g. Select → story form), or story list ↔ story page (`tbScreenIs`)). Popups use a bottom sheet. The selected tab's icon is filled.
  - **There is no Test tab** (removed v2.39.0): the words test lives in Words → Test, story tests in Story → Test. `testPane` ('schedule' = words, 'story') says which one is showing; `openWordsTest()` / `openStoryTest(id)` navigate there; `setQuit` moves the timer/Hint/Quit box `#testBarR` into the header of the right tab (`#dictBarEl` / `#storyBarEl`); `testSegHide` hides that tab's sub-tabs during a test; `tmrShould` counts only while that test pane is on screen.
  - **Story reader + slash reading (끊어읽기)**: a story page has play ▶/⏸ (resumes where it paused, `srPos`), stop ■, translate toggle and a level dropdown `#svLv` (No chunks / Small / Medium / Large chunks = `none|s|m|l`, in that order); ⋯ (`openStoryMenu`, bottom sheet) has text size Small/Large (per device, localStorage `wm.srFont`), Slash reading settings, Edit story, Delete story. **No chunks** = the classic view (tappable words, study words as buttons, Google paragraph translations `s.ko`, sentence-by-sentence reader `startReading`). A slash level shows chunks (`slashHTML`: EN over KO, orange `/`, study words bold; tap a chunk to play from it) from `s.chunks` (`{title, sentences:[{en,ko,s,m,l}]}`, valid while `s.chunkSrc===s.text`, synced with the word list, kept in `mergeData`), generated once by **the AI chosen in Me → Settings → AI** (`loadChunks`: the text is cut into parts of a few paragraphs (~700 chars, `chunkBatches`), up to 4 requests at a time with a "done / total · seconds" line (`chunkJobs`, `chunkTick`), each `chunkPart` → `aiComplete(…, {maxTokens:16000, stream:true})` — Claude is streamed (`claudeStream`, SSE, gives up only after 60 s with no data) so long replies are not cut off, same key/model as the story writer, called from the browser; `CHUNK_PROMPT` kept exactly as the original slash-reader prompt, checked by `chunkValid`, one retry; no AI key → a message pointing to Settings → AI; ≤8,000 chars); sentences are mapped back to paragraphs by `slashParas`. Playback (`slashPlay`): each chunk EN at the slash speed, then (translation on) its Korean (ko-KR voice, speed +0.1), then the pause; uses the app's Voice engine (`srSay` → `gSay(text,voice,rate)` / `lpDevice(text,ko,rate)`). Changing level keeps the sentence position. Settings `slashLevel/slashTr/slashRate/slashPause` (default none / on / 0.9 / 1 s) are account settings (`slashCfg`, `setSlash`), also on Me → Settings → **Slash reading** (`renderSlash`: level cards with examples, speed 0.7–1.1, pause 0–2 s, translation show/hide).
  - **Video tab** (ported from the video-repeat-player app, v2.40.0; `s-video`, state object `V`, icons `VI`): list pane `#vpane-list` (link box + Paste + Go, `vExtract` accepts youtu.be / watch?v= / shorts / embed / bare id; recent videos `V.hist` with thumbnail, day, ✕) and player pane `#vpane-play` (`openVideo(vid)` pushes `{video}` history state so the back gesture returns, `closeVideo`; the big header hides, `body.vplay`). YouTube IFrame API loaded on first use (`vYTReady`), `controls:0`, captions module unloaded; title from YouTube oEmbed. Under the video: progress bar (drag to seek, keeps the drill going), "time / total" and "n / total", a row of square buttons (video on/off, ← previous, −N s, replay (green), +N s, next →, CC = off/KR/EN caption on the video), and pill toggles: **Repeat 3×** / Play once, 🐢 slow (`setPlaybackRate`), Translate (Korean under each sentence), Blur, Time (per-sentence start/end with < > 0.5 s adjust, saved). Tapping a sentence = `vPlaySingle`: 3-pass drill (pass 1 no caption, 2 Korean, 3 English, 1 s pauses; `vStartTracker` 50 ms) then, when started from ←/→/video tap, the next sentence; Play once flows straight on. Tapping the video plays/pauses. ⋯ sheet: Sync subtitles (± 0.1 s per video, localStorage `wm.vsync.<vid>`), Clear subtitles (asks), Video settings. No transcript → paste box (link to youtubetotranscript.com, `[HH:MM:SS] text` lines → `vParseStamped` → `vSentences`, same sentence splitting as the original). Translations use the app's Google Translate key (`translateManyKo`, 100 per request). The last sentence is kept per video (`s` in history) and highlighted when reopened. Leaving the tab pauses (`vPause`). Landscape phone (max-height 500px): only the video and its controls. Me → Settings → **Video** (`renderVideoSet`): back seconds 1/2/3/5/10, forward 5/10/15/30, slow speed 0.5–0.9 (account settings `videoRewind/videoForward/videoSlow`), Clear video history (tap twice). Guests keep transcripts/translations/history in localStorage (`wm.v.transcript.<vid>`, `wm.v.translations.<vid>`, `wm.vhist.guest`).

  - Me → Settings is a list menu (`SETTINGS_MENU` in the script); each item opens its own page with a ‹ back button, and the phone/browser back gesture also returns. Add future settings to that list.
  - While a test runs (words or story) the fixed header of its tab (Words or Story) shows a **timer** (`tmr`, m:ss, counts only while that Test pane is on screen and the app is visible — `tmrSync` on tab change/visibilitychange), a **📖 Words** button for story tests (`toggleStoryHint` puts the keyboard away and slides up `#hintPop` with the story's words; focusing any blank or ✕ closes it — `hideStoryHint`) and **Quit**, which asks first (`confirmQuit` sheet). Quitting a story test saves nothing.

The **Write with <AI> / Write again** button that uses the "Words to learn" box (plain words or JSON). The story is only filled in; the user reviews and taps Save.
  - **Language** (Me → Settings → Language, `#me-lang`, `renderLang`): System default / English / 한국어, stored per device in localStorage `wm.lang` (`auto` default → `DEVICE_LANG` from `navigator.languages`); changing it reloads the app. `LANG`/`LOC()` set `<html lang>` and date formatting. Korean is done by a DOM translator: `I18N_KO` (exact strings) and `I18N_KO_RE` (regex patterns for strings with numbers/names), applied by `trTree` + a MutationObserver to text nodes and `placeholder`/`title`/`aria-label`. Learning content is never translated (`I18N_SKIP` selectors, or `data-noi18n`). **When adding or changing UI text, add its Korean to `I18N_KO` (or a pattern to `I18N_KO_RE`).** Brand/model names, external site button names, AI prompts and speech stay English.
  - Translation: toggle button next to each example sentence → Korean via Google Cloud Translation v2, called from the browser with the user's own API key (Me → Settings → Google Translate). Translations are saved on the card (`exKo`).
- **Backend**: `src/index.js` — Cloudflare Worker
  - `POST /api/auth/login` — verifies a Google ID token, creates a session (KV, 60 days)
  - `POST /api/auth/logout`, `GET /api/me`
  - `GET/PUT /api/words` — the signed-in user's whole word list and answer log (`wm:words:<google sub>` → `{cards, seed, log, history, stories, updatedAt}`); PUT takes `base` and returns 409 `{conflict, data}` when the stored copy is newer
  - `GET/PUT /api/journal` — the user's journal (`wm:journal:<sub>` → `{entries, updatedAt}`); PUT merges with the stored copy per entry (later `updated` wins; deletions kept as tombstones for 60 days) and returns the merged list
  - `POST /api/auth/totp`, `GET/DELETE /api/totp`, `POST /api/totp/setup`, `POST /api/totp/confirm` — authenticator-app sign-in (see Auth)
  - `GET/PUT/DELETE /api/video/transcript?v=`, `GET/PUT /api/video/translations?v=`, `GET/PUT /api/video/history` (signed in): transcripts `wm:vt:<vid>` and translations `wm:vtr:<vid>` are shared per video (1 year; DELETE leaves a `{deleted:true}` marker); history `wm:vhist:<sub>` (max 100). Falls back to the old app's KV (binding `VIDEO_CACHE`, read only: `<vid>`, `tr:<vid>`, `hist:<email>`).
  - `GET/PUT /api/settings` — the signed-in user's settings, Google Translate API key, AI provider and keys (`wm:settings:<google sub>` → `{translateKey, aiProvider, openaiKey, openaiModel, geminiKey, geminiModel, claudeKey, claudeModel, slashLevel, slashTr, slashRate, slashPause, videoRewind, videoForward, videoSlow}`; `SETTING_FIELDS`). Guests keep settings in localStorage.
  - `GET /api/lookup?word=` — Merriam-Webster Learner's (definition, examples, pronunciation) + Merriam-Webster Thesaurus (similar words), asked together. **Similar words: at most 3** — up to 8 candidates from the thesaurus's main sense (topped up from other senses only if fewer than 3), ranked by `freqRank` (word-frequency list `src/freq.js`, 20k most common English words from google-10000-english, personal/educational use) and the 3 most common kept; empty when MW has none. Cached in KV (`wm:dict3:<word>`, 90 days) once the Thesaurus has answered. `&fresh=1` skips the cache; `&debug=1` adds a `sources` report.
  - No other similar-word source (Datamuse was removed): similar words are optional. The 3-word limit applies only when words are generated (lookup, photo import); existing cards keep and show all their similar words.
- **Secrets** (Cloudflare dashboard → Worker → Settings → Variables and Secrets, never in the repo): `MW_LEARNER_KEY`, `MW_THESAURUS_KEY`. (Slash reading needs no server secret: it uses the user's own AI key.) Without the Learner's key, lookups return "unavailable"; without the Thesaurus key, words have no similar words.
- **Storage**: Workers KV namespace `word-memory`, binding `WORDS`. Keys start with `wm:`. Second binding `VIDEO_CACHE` = the old video-repeat-player namespace (read only).
- **Auth**: Google Identity Services, same OAuth client as video-repeat-player. **Authenticator-app sign-in (TOTP)** replaced the email-code idea (no mail service needed): Me → Settings → **Authenticator app** (`renderAuth`, signed-in Google users only) → `POST /api/totp/setup` gives a secret + `otpauth://` URI, shown as a QR code (qrcode-generator 1.4.4, loaded on demand from jsDelivr, cdnjs fallback; the key is shown too, with Copy) → the user confirms with a 6-digit code (`POST /api/totp/confirm`) → `wm:totp:<sub>`; Turn off = `DELETE /api/totp`. Gate → "Sign in with an authenticator app": Google email + code → `POST /api/auth/totp` (email must be linked: `wm:email:<email>` written by `linkEmail` at Google sign-in and on `GET /api/settings`); RFC 6238 (SHA-1, 6 digits, 30 s, ±1 step), a used step can't be reused, 5 wrong tries per email per 10 minutes; returns the same `{session, user}` as Google sign-in. The last email used is prefilled (`wm.totpEmail`). The gate scrolls (`#gate{overflow-y:auto}`) and focusing the email/code field scrolls the box to the top so the keyboard doesn't cover it.
